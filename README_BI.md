# BI Integration Guide — enterprise_security_data.csv

`enterprise_security_data.csv` is generated by `scripts/unified_bi_prep.py`. It aggregates findings from every S3 and IAM audit JSON export into a single flat table, ready for direct import into **Google Looker Studio (V1)** and **Microsoft Power BI (V2)**.

---

## Column Reference

| Column | Type | Description |
|---|---|---|
| `Source_File` | Text | JSON filename the row originated from — use to filter by scan run |
| `Scanner` | Text | `S3 Security Scanner` or `IAM Security Scanner` |
| `Scan_Timestamp` | DateTime | UTC timestamp of the scan that produced this finding (`YYYY-MM-DDTHH:MM:SSZ`) |
| `Scan_Region` | Text | AWS region audited (e.g. `us-east-1`) |
| `Resource_ID` | Text | Affected resource — S3 bucket name or IAM username |
| `Control_ID` | Text | Primary NIST control identifier (e.g. `NIST-SC-28`, `NIST-IA-2(1)`) |
| `Severity` | Text | `Critical`, `High`, `Medium`, or `Low` |
| `Status` | Text | `FAIL` (non-compliant) or `PASS` (compliant) |
| `Risk_Weight` | Integer | Numeric score: Critical=10, High=7, Medium=4, Low=1 |
| `Reason` | Text | Technical description of the misconfiguration detected |
| `Remediation` | Text | Recommended corrective action |
| `ISO_Mappings` | Text | ISO/IEC 27001:2022 control(s) mapped to this finding (e.g. `ISO-27001-A.8.24`) |

## V1 — Google Looker Studio

### Connecting the Data Source

1. Open [Looker Studio](https://lookerstudio.google.com) and click **Create → Report**.
2. Select **File Upload** as the connector.
3. Upload `enterprise_security_data.csv`.
4. Looker Studio will auto-detect column types — verify:
   - `Scan_Timestamp` is set to **Date & Time**
   - `Risk_Weight` is set to **Number**
   - All other columns are **Text**

### Recommended Charts

| Chart Type | Dimension | Metric | Purpose |
|---|---|---|---|
| Scorecard | — | `SUM(Risk_Weight)` filtered to `Status = FAIL` | Total risk exposure at a glance |
| Bar chart | `Severity` | `COUNT(Resource_ID)` | Finding distribution by severity |
| Pie chart | `Scanner` | `COUNT(Resource_ID)` filtered to `Status = FAIL` | S3 vs IAM failure share |
| Table | `Resource_ID`, `Control_ID`, `Severity`, `Risk_Weight` | — | Drill-down finding list |
| Time series | `Scan_Timestamp` | `SUM(Risk_Weight)` | Risk trend over successive scans |
| Bar chart | `Control_ID` | `COUNT(Resource_ID)` filtered to `Status = FAIL` | Most-violated controls |

### Calculated Field — Risk Score Label

In **Resource → Add a field**, create:
```
CASE
  WHEN Risk_Weight >= 10 THEN "Critical"
  WHEN Risk_Weight >= 7  THEN "High"
  WHEN Risk_Weight >= 4  THEN "Medium"
  ELSE "Low"
END
```

## V2 — Microsoft Power BI

### Connecting the Data Source

1. Open Power BI Desktop and select **Get Data → Text/CSV**.
2. Browse to `enterprise_security_data.csv` and click **Load**.
3. In the **Power Query Editor**, verify column types:
   - `Scan_Timestamp` → **Date/Time**
   - `Risk_Weight` → **Whole Number**
   - All other columns → **Text**
4. Click **Close & Apply**.

### Recommended Visuals

| Visual | Fields | Purpose |
|---|---|---|
| Card | `SUM(Risk_Weight)` with `Status = FAIL` filter | Total weighted risk score |
| Clustered bar | Axis: `Severity`, Value: `Count of Resource_ID` | Finding volume by severity |
| Donut chart | Legend: `Scanner`, Value: `Count of Resource_ID` | Scanner contribution |
| Matrix | Rows: `Resource_ID`, Columns: `Control_ID`, Values: `Risk_Weight` | Risk heat map per resource |
| Line chart | Axis: `Scan_Timestamp`, Value: `SUM(Risk_Weight)` | Risk trend over time |
| Slicer | `Scanner`, `Severity`, `Status` | Interactive filtering |

### DAX Measure — Total FAIL Risk Weight

In **Modeling → New Measure**:
```dax
Total Risk Weight =
CALCULATE(
    SUM(enterprise_security_data[Risk_Weight]),
    enterprise_security_data[Status] = "FAIL"
)
```

### DAX Measure — FAIL Rate

```dax
Fail Rate =
DIVIDE(
    COUNTROWS(FILTER(enterprise_security_data, enterprise_security_data[Status] = "FAIL")),
    COUNTROWS(enterprise_security_data),
    0
)
```

Format as **Percentage** in the visual properties pane.

## Regenerating the CSV

Run this after every audit to refresh the dataset:

```bash
# Generate fresh audit data and immediately rebuild the BI export
uv run aws-audit all --export-json --stale-key-days 0 && \
uv run python scripts/unified_bi_prep.py
```

The script reads **all** matching JSON files in the current directory — each audit run adds a new file, so the CSV accumulates historical scan data automatically, enabling trend analysis across time in both tools.
